# 需求说明: AI 机器人（Bot）

## 背景

AnonChat 的随机匹配和漂流瓶在用户少的时段会出现"排队很久没人"、"瓶子没人回"的情况。本包引入 AI 机器人：机器人以普通匿名身份参与聊天，按绑定的角色卡人设回复，并能发送后台媒体库里的图片和视频。

## 已确认的产品决策（2026-11-06，用户确认）

1. 不在国内部署；项目不开源。
2. **用户不会被告知对方是机器人**：任何对外接口（WS 推送、REST 响应、匹配结果）都不得出现能区分 bot 和真人的字段或行为特征。只有管理后台能看到 bot。
3. 模型接入：**OpenAI 兼容协议**（DeepSeek、OpenRouter、通义等均可），通过 `BASE_URL + API_KEY + MODEL` 配置，每个 bot 可以单独指定模型。
4. 必须利用服务商的提示词前缀缓存（prompt caching）降低成本。
5. 媒体由后台管理：可创建文件夹、上传图片和视频，每个媒体有标签；bot 绑定一个媒体文件夹，回复时按标签挑选。**不需要生成图片。**
6. 限额：对每个 bot 分别设置：
   - 总上限：token 数和回复条数各一个；
   - 滑动窗口上限：token 数和回复条数各一个；
   - 每个对话的上限：回复条数，以及同一对话内两次回复的最小间隔。
7. 回复要有节奏，不能每条都秒回：先读消息，再显示"正在输入"，按打字速度发出；用户连发几条会合并成一次回复。
8. 首期玩法：
   - 随机匹配：用户排队 N 秒仍无真人配对时，由 bot 兜底；
   - 漂流瓶：bot 隔一段时间挑一个没人回复的瓶子回复。
   - 聊天室、私密链接、故事书**不接入** bot。
9. 管理端：后端 API 和管理后台页面都要做（角色卡、bot 设置、媒体库、用量统计）。

## 成功标准

- 用户排队超过 `BOT_MATCH_FALLBACK_AFTER` 仍未配对时收到 `match.found`，对方是符合其筛选条件（清流模式、VIP 性别、同省偏好）的 bot。
- bot 的回复符合角色卡人设，带随机延迟和 typing 事件，可以发图片和视频；用户能在聊天界面看到并播放。
- 任一限额触发后，bot 停止消耗：不再接新对话；进行中的匹配对话以 `peer_left` 结束。
- 每次调用都记录 token 用量和缓存命中的 token 数，后台可以看到。
- 用户侧的所有接口都无法区分 bot。
- 已有测试全部通过；新增的单元测试和集成测试覆盖核心路径。
