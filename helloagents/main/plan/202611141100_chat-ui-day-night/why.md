# 为什么：匹配与聊天界面改版 + 白天/夜晚模式

## 背景

用户反馈「匹配、聊天界面的操作逻辑和样式有点丑」。2026-11-14 做了可交互样式稿（claude.ai Design 画布「AnonChat 匹配与聊天 样式稿」），用户确认：

- 交互方案可以，按样式稿实施；
- 配色采用两套：**A 暮紫**作为夜晚模式、**E 奶白**作为白天模式。

## 现状问题（已对照代码确认）

1. 匹配入口重复：首页有「匹配」，`/match` 的 idle 页又有一个「开始匹配」；取消/离开后落到 idle 页像死胡同。
2. `match.found` 后直接进入空聊天框，没有过渡、没有对方信息和开场引导；切到后台时匹配成功无提醒。
3. ended 状态整屏替换，聊天记录消失。
4. 头部「下一个/离开/屏蔽/举报」等权重、无确认；「←」与「离开」语义重叠；移动端用 `<details>` 做菜单。
5. 每条消息都带头像和昵称、不分组；气泡宽度被双重 max-w 压缩；系统消息按普通成员渲染；无时间分隔、无「新消息」提示。
6. 渐变滥用（返回键、发送键、自己气泡都是渐变，且两套渐变不一致）；图标全是 emoji/字符。
7. 输入框固定 2 行、字数常显、「发送」两字挤在 44px 圆里、上传时按钮文字替换导致跳动。
8. 自己气泡白字在 `#8B7CF6` 上对比度只有 3.3:1；次要文字 `#8E8E93` 在气泡上不达标。
9. 移动端 `h-screen`（100vh）被地址栏/键盘顶歪，未处理安全区。
10. 聊天页强制暗色，从浅色大厅进入时整屏突变。

## 目标

- 匹配流程：搜索 → 匹配成功过渡 → 聊天（对方名片 + 破冰语）→ 原地结束 → 再来一个。
- 聊天头部只常驻「换一个」（两次确认），举报/屏蔽收进「⋯」底部菜单，返回需确认。
- 通用聊天组件（气泡、消息列表、输入框）按新规范重做，所有聊天页受益。
- 白天/夜晚两套 token，聊天页跟随用户主题，不再强制暗色；未设置时跟随系统。

## 范围外

- 后端、WS 协议、数据库：不改。
- 管理后台样式：不改（仍强制浅色）。
- 大厅/首页布局：不改（只受主题 token 默认值影响）。
- 消息失败重试的数据流（`useChat` 目前不产生 failed 状态）：不新增，只保留 MessageList 已有的展示能力。
