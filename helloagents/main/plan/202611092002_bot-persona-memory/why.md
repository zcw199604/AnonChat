# 变更提案: Bot 人设包、双核驱动与长期记忆

## 需求背景

上一包（`202611062351_ai-bot`）已经实现了 AI 机器人：bot 以普通匿名身份参与随机匹配和漂流瓶，按角色卡回复，能发媒体库里的图片和视频，有节奏控制和限额。和社区里成熟的陪伴类项目（SillyTavern、KouriChat、Neptunia、LumiMuse、HakoniwaRPD）相比，还差这些：

1. **角色卡生态不通**：只能在后台手填 7 个字段，不能导入社区的 SillyTavern 角色卡（V1/V2 JSON、PNG），也不支持 V2 的 `alternate_greetings`、`post_history_instructions`、`character_book`（世界书）。
2. **没有长期记忆**：bot 只看当前会话最近 60 条消息。同一个用户再次遇到这个 bot（重新匹配，或 bot 捞到他的漂流瓶）时，bot 对他一无所知。
3. **没有关系演化**：bot 对每个用户的态度都一样，没有好感度，也没有情绪。
4. **人设表达单一**：只有一段 system 提示词。没有 KouriChat `.krp` 那样的"心核 / 智核"分工，没有表情包，也没有内置工具；模型输出偶尔会变成客服腔、Markdown，甚至漏出设定内容。

## 已确认的产品决策（2026-11-09，用户确认）

1. 四项都做：①兼容 SillyTavern V2 角色卡导入；②按用户的长期记忆；③好感度与情绪；④跑偏检测和表情包回复。
2. 参考 KouriChat 的 `.krp` 人设目录（`index.toml` + `heart.prompt` / `reason.prompt` 双核 + `expressions/` + 内置 tools），支持导入这种人设包。
3. **长期记忆用 Go 原生实现**：参考 memobase 的"用户画像 + 事件时间线"思路，复用现有 Postgres 和 LLM 客户端，不部署 memobase、mem0 等外部服务。（memobase 最后一次提交是 2026-01-11，之后停更。）
4. **记忆保留期**：bot 和对方最后一次互动后 30 天自动删除（后台可在 1–365 天之间调整）。用户重置匿名身份后，旧记忆不再关联新身份；旧身份吊销后，它的记忆在下一次清理时删除。后台可以查看和删除记忆。
5. 实施者：Codex（`gpt-6.1-sol`，medium）。审查者：Claude。

## 变更内容

1. 角色卡扩展：心核与智核人设、备选开场白、历史后指令、世界书、启用的内置工具、表情包、来源格式。
2. 角色卡导入：SillyTavern V1/V2/V3（JSON / PNG）和 `.krp` 人设包（zip）。
3. 双核驱动：bot 可以选择 `dual` 模式。智核先读记忆、调用内置工具、决定情绪、好感度变化和表情包，心核再按智核给的要点说出角色化的回复。
4. 长期记忆：每个 bot 对每个对方身份分别维护一份画像、一条事件时间线、好感度和情绪。由后台任务分批抽取，回复时注入。
5. 跑偏检测：检测 Markdown、客服腔、设定泄露、超长等风格问题，重写一次，仍不合格时做清洗。
6. 表情包：按人设的表情列表发送，作为图片消息。
7. 后台：导入入口、角色卡新字段的编辑、表情包管理、bot 的双核与记忆开关、全局设置（智核模型、记忆模型、保留期、抽取间隔、跑偏检测开关）、记忆查看与删除、按类型拆分的用量统计。

## 范围边界

- **范围内:** 上面 7 项；匹配会话和漂流瓶两种场景（与上一包一致）。
- **范围外:**
  - `.krp` 的 `tools/*.py`：不执行上传的代码，只支持 Go 内置工具白名单（见 how.md ADR-2）。
  - `.krp` 的 `[[commands]]`（`/命令` 触发）：匿名陌生人不会知道这些命令，用了反而暴露 bot。导入时忽略并给出警告。
  - 角色卡导出（ST / `.krp`）、PNG 头像作为 bot 头像、语音、生图、主动发消息（bot 主动找人聊天）。
  - 匹配时优先分配"认识的 bot"（记忆连续性调度），留作后续。
  - 向量检索和 embedding（事件检索用关键词加时间，见 ADR-3）。
  - 聊天室、私密链接、故事书接入 bot。

## 影响范围

- **模块:** `backend/internal/bot`（新增 `persona/` 子包和若干文件）、`internal/media`（复用）、`internal/jobs`（清理）、`internal/api`（路由）、`frontend/src/features/admin`。
- **API:** 只新增和扩展 `/api/admin/*` 后台接口；**用户侧接口零变更**。
- **数据:** 迁移 `00009_bot_persona_memory.sql`，只做加法。
- **依赖:** `github.com/BurntSushi/toml` 从间接依赖提升为直接依赖（已在 go.sum 中，版本不变）。

## 核心场景

### 需求: 角色卡导入
**模块:** bot/persona、bot 后台接口、前端角色卡面板

#### 场景: 导入 SillyTavern V2 PNG 角色卡
运营者在后台上传一个带 `chara` 元数据块的 PNG。
- 新建一张角色卡，字段按 how.md §3.2 的映射填好，`source_format=st`。
- `alternate_greetings`、`post_history_instructions` 和世界书条目都保留下来。
- 不支持的字段写进 `extensions`，响应里带 `warnings`。

#### 场景: 导入 `.krp` 人设包
运营者上传一个 zip，里面是 `xxx.krp/` 目录（或这些文件直接放在 zip 根目录）。
- `heart.prompt` 和 `reason.prompt` 分别写入心核、智核人设。
- `expressions/index.json` 里列出的图片存进一个自动创建的表情文件夹，每一项生成一条表情记录（key + 说明）。
- `tools/*.py` 和 `[[commands]]` 被忽略，并在 `warnings` 里列出名字。
- zip 里有路径穿越、超出大小或数量上限、非图片文件冒充表情时，整包拒绝，不留下残缺数据。

### 需求: 双核驱动
**模块:** bot/reason、bot/engine

#### 场景: dual 模式回复
bot 的 `core_mode=dual`，对方发来消息。
- 先调用智核（可以调用最多 2 轮内置工具），得到内心想法、回复要点、情绪、好感度变化、要发的表情、是否沉默。
- 再调用心核生成气泡；智核选中的表情在文本气泡之后发送。
- 本轮进行中对方又发了新消息时，不发送表情（参考 KouriChat 的打断语义）。
- 智核失败或输出无法解析时，本轮按 single 模式继续，不影响回复。

#### 场景: single 模式
`core_mode=single`（默认）时只调用一次心核，行为和现在一致，只是多了记忆、好感度和表情包的注入。

### 需求: 长期记忆与好感度
**模块:** bot/memory、jobs

#### 场景: 再次遇到同一用户
用户 U 和 bot B 聊过，记忆已经抽取。之后 U 再次匹配到 B，或者 B 捞到了 U 的漂流瓶。
- B 的提示词里带上它对 U 的画像、最近的事件、好感度阶段和当前情绪。
- 另一个 bot B2 看不到这些记忆，记忆按 bot 隔离。

#### 场景: 记忆抽取
会话结束、对方新消息累计达到 `memory_extract_every` 条，或者对方 10 分钟没有新消息时：
- 后台任务把新消息交给记忆模型，更新画像、追加事件、调整好感度。
- 这次调用的 token 记入 bot 用量（`kind=memory`）。bot 已超限、已停用或关闭了记忆时不抽取。

#### 场景: 记忆过期与身份重置
- 超过保留期没有互动的记忆，下一次清理时删除。
- 对方身份已吊销（重置过身份）的记忆，下一次清理时删除。

### 需求: 跑偏检测
**模块:** bot/ooc

#### 场景: 输出出现 Markdown 或客服腔
- 检测命中时，带纠正指令重新生成一次（`kind=retry`）。仍然命中就做清洗：去掉 Markdown 标记，删掉泄露设定的行。
- **不检测、不过滤**任何关于"是不是 AI"的表述（上一包硬约束 §0.2）。

### 需求: 后台管理
**模块:** 前端 admin

#### 场景: 查看和删除记忆
运营者在 bot 详情里打开"记忆"，看到每个对方的匿名编号、好感度、情绪、事件数、最后互动时间，可以查看画像和事件，可以删除单条记忆或清空。每次查看和删除都写审计日志。

## 风险评估

- **风险:** 双核让每轮的 LLM 调用和 token 翻倍以上。
  **缓解:** 默认 `single`；dual 按 bot 开启；智核可以单独指定更便宜的模型；智核有自己的缓存键，前缀保持稳定；所有调用都计入 bot 限额。
- **风险:** 记忆是从用户消息里提炼的隐私数据，保留期比消息（168h）长。
  **缓解:** 用户已确认 30 天保留；按 bot 隔离；身份吊销后删除；对用户侧接口完全不可见；后台查看写审计；日志里不打印记忆内容。
- **风险:** 上传的 zip / PNG 是不可信输入（zip 炸弹、路径穿越、伪造图片）。
  **缓解:** how.md §3.4 的硬性限制（总大小、条目数、单文件大小、路径校验、MIME 嗅探），只接受管理员上传。
- **风险:** 表情包会增加"会发图的就是 bot"这个特征（普通用户目前不能发图）。
  **缓解:** 沿用上一包已接受的风险；每轮最多 1 个表情，并受 `conv_media_limit` 约束。本包不改用户侧发图能力。
- **风险:** bot 记得用户、能叫出用户提过的事，可能让用户察觉这是同一个 bot。
  **缓解:** 这符合陪伴产品的定位；记忆块的提示要求"自然地想起，不要逐条复述"。
