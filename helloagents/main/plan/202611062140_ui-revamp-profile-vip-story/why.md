# 变更提案: 界面改版 + 资料与匹配偏好 + VIP 激活码 + 公告广播 + 故事书

目录: `helloagents/main/plan/202611062140_ui-revamp-profile-vip-story/`
前置: V1 方案包 `202611061637_anonchat-v1-v2` 的 V1 部分（任务 1–14.1）已完成并部署在 cch_hk。

## 背景

V1 已经能跑，界面还只是功能性的暗色 slate 风格。用户这次给了两份输入：

1. **视觉规范**：薰衣草紫品牌色。大厅用浅色 Bento Grid，聊天页用柔和的暗色玻璃拟态，从大厅进入聊天时有一段浅色到暗色的过渡。
2. **首页元素清单**：来自一张参考截图。用户已确认"全部做成真功能"。
   - 顶部：汉堡菜单、品牌名、邀请好友、添加到主屏幕、主题切换。
   - 公告跑马灯、广播卡。
   - 个人资料卡：头像、匿名编号（可复制）、分享、换身份、折叠、昵称（随机 / 编辑）、性别、年龄、城市（是否公开）、清流模式、标签。
   - 匹配偏好：按性别、同省。这两项是 VIP 权益，未开通时盖一层"激活码解锁 VIP 特权"浮层。
   - 一个大的"匹配"按钮。
   - 右下角浮动入口："匿名信"和"故事书·公测"。

品牌名用 **AnonChat 匿名聊天**（副标题 ANONYMOUS CHAT），不照搬参考截图的品牌、配色和文案。

## 目标

- 前端整体改版，严格落实用户给的 token 和两种页面风格。
- 资料、匹配偏好、清流模式、VIP、公告、广播、故事书全部有后端支撑，不做摆设。
- 不破坏 V1 已有的安全基线：匿名优先、Origin 校验、限流、违禁词、封禁、7 天留存、防泄漏测试。

- V1 方案包中的 V2 任务（Redis、图片、Web Push 等），仍按原方案包推进。

## 关键场景

1. **首次进入**：看到浅色大厅，资料卡展示随机昵称和匿名编号。点"匹配"后背景在 300ms 内过渡到暗色，进入排队。
2. **清流用户**：开启清流模式后，只会和同样开启了清流模式的人配对。排队超过 30 秒时，页面提示"清流用户较少，可关闭清流模式扩大范围"，但不会自动放宽。
3. **VIP 用户**：兑换激活码后，可以设置"只匹配女生"并开启同省匹配。这两个硬条件不会自动放宽；排队页显示当前生效的偏好，用户可以取消。
4. **非 VIP 用户**点击性别筛选时，弹出激活码兑换框。服务端也会忽略非 VIP 用户提交的偏好（以服务端为准）。
5. **广播**：用户用广播卡提交一条广播，状态为待审核。管理员通过后，广播出现在首页广播卡和匿名动态中，展示 24 小时。被驳回时退还广播卡。
6. **故事书**：A 发起故事《雨夜书店》，选择扮演"店主"。B 在故事大厅认领"旅人"后开演。双方各发言至少 5 条且时长满 5 分钟，结束时判定为有效场次。A 申请收录，B 同意后，作品进入审核；通过后出现在故事书书架和匿名动态中。
7. **换身份**：旧身份的会话全部离开。VIP 到期时间和剩余广播卡转移到新身份；资料重置为默认值，匿名编号重新生成。

## 风险与约束

| 风险 | 级别 | 应对 |
|---|---|---|
| 性别、年龄、省份属于个人信息 | 高 | 都是自愿填写，默认"保密 / 未设置 / 不公开"。省份只在用户开启"公开"后才展示给对方。不展示昵称历史、在线时长、注册时间。防泄漏测试覆盖新增字段 |
| 激活码被暴力枚举 | 中 | 16 位 Crockford Base32（80 bit），库里只存 sha256；按身份和 IP 双重限流（每 10 分钟 5 次）；兑换操作写入 access_logs |
| 售卖激活码的经营合规（虚拟商品、发票、未成年人） | 中 | 站内不接支付；年龄下限 18；用户协议中的 VIP 条款列入 HITL 清单 |
| 广播和故事作品属于公开 UGC，有监管要求 | 高 | 先过违禁词过滤，再人工审核，通过后才公开；支持举报和下架；所有审核动作写入 admin_audit_logs |
| 故事作品要长期保存，与"聊天记录保留 7 天"冲突 | 中 | 作品是双方明确同意后生成的快照（只含角色名和正文，不含身份），属于用户主动发布的内容，不受 7 天留存约束。作者可以删除；任一方撤回同意时作品下架 |
| 带硬条件的匹配可能长期等不到人 | 低 | 排队页显示等待时长和当前条件，30 秒后给出放宽建议，可以随时取消 |
| 新增依赖 | 低 | 只加 `@fontsource-variable/inter`（打包进静态资源，满足 CSP `font-src 'self'`）。二维码等功能不引入新库 |
| 改版导致 E2E 选择器失效 | 中 | 保留现有 `data-testid`，改版批次必须让现有单元测试和 E2E 全部通过 |

## 成功标准

- 视觉规范逐条落实。禁止项（真人头像、超过两个强调色、重阴影、快节奏动效、身份历史信息）都由检查清单覆盖。
- 首页截图中的元素都能使用，并且都有对应的后端接口和测试。
- 后端 race 测试、集成测试、vet、staticcheck、govulncheck 都通过；前端测试、typecheck、lint、build、audit 都通过；E2E 覆盖：资料设置、VIP 兑换、按偏好匹配、广播审核、故事书完整流程。
