# 变更提案: AnonChat 匿名聊天平台（V1 + V2）

## 需求背景

仓库目前是空项目，只有 `README.md`。目标是做一款**准备公开上线**的匿名聊天 Web 应用，后端用 Go，前端用 React，数据存 PostgreSQL，用 Docker 部署。需要同时支持四种聊天形态：

- **A 随机匹配**：系统随机配对两个陌生人进行 1v1 实时聊天，可以跳过换下一个。
- **B 聊天室**：按话题进入房间，多人匿名群聊。
- **C 漂流瓶**：异步投放一段文字，被别人捞到后可以回复，形成一个异步私聊。
- **D 私密链接聊天**：生成一个链接发给熟人，两人私聊，支持阅后即焚，聊完可以销毁。

所有双方聊天记录在服务端保存 **7 天**，到期自动清除。

## 产品分析

### 目标用户与场景
- **用户群体:** 想倾诉、想找陌生人聊天，又不想暴露身份的 Web/移动浏览器用户。
- **使用场景:** 无聊时随机找人聊；按兴趣进房间；深夜投个漂流瓶；跟熟人临时开一个"不留痕"的私聊。
- **核心痛点:** 现有社交软件绑定真实身份和长期关系链，说话有顾虑；匿名平台又常被广告和骚扰淹没。

### 价值主张与成功指标
- **价值主张:** 不用注册，打开就能聊；对其他用户完全匿名；骚扰可以一键屏蔽和举报，并且确实会被处理。
- **成功指标（上线后观测）:**
  - 首次打开到发出第一条消息 ≤ 10 秒（无需注册）。
  - 随机匹配在 50+ 人排队时，P95 等待时间 ≤ 10 秒。
  - 单实例支持 5,000 个并发 WebSocket 连接，消息端到端 P95 延迟 ≤ 300ms。
  - 举报 24 小时内处理率 ≥ 95%（运营指标，由管理后台支撑）。

## 变更内容

**V1：可公开上线的最小完整版本**
1. 工程骨架：Go 后端、React 前端、PostgreSQL、迁移、Docker Compose、Caddy 边缘代理（HTTPS）。
2. 匿名身份：免注册，生成随机昵称和头像，可一键换身份；可配置"前台匿名、后台实名"的手机号验证开关。
3. 实时网关：WebSocket、统一消息协议、心跳、断线重连和补拉消息。
4. 四种聊天形态 A/B/C/D（只支持文本和表情）。
5. 消息持久化，7 天自动清除；审计和访问日志按合规要求另行保留。
6. 内容安全：敏感词过滤、频率限制、屏蔽、举报（保存证据快照）、封禁（身份/IP/实名账号）。
7. 管理后台：管理员登录、举报处理、封禁管理、基础统计、操作审计。
8. 生产部署：Docker 镜像、Compose 编排、安全响应头、数据库每日备份。

**V2：规模化与体验增强**
1. 引入 Redis，支持多实例水平扩展（跨节点消息广播、共享在线状态、匹配队列和限流）。
2. 匹配偏好：兴趣标签、语言，等不到时自动回退到随机匹配。
3. 图片消息：对象存储（MinIO/S3 兼容）、去除 EXIF、审核接口，同样 7 天过期。
4. 用户自建房间：公开/私密（密码 + 邀请链接）、房主踢人和禁言、不活跃自动归档。
5. 人机验证：在创建身份、发短信和触发风控时要求验证。
6. 管理增强：管理员两步验证（TOTP）、敏感词在线管理和热更新、房间治理、审计日志查询。
7. PWA 与 Web Push：可安装，漂流瓶回复和私密消息可以推送通知。
8. 可观测性：Prometheus 指标、可选的 Grafana 面板。

## 范围边界
- **范围内:** 上述 V1 和 V2 全部条目，包括 Web 端（桌面和移动浏览器自适应）、管理后台和 Docker 部署。
- **范围外:**
  - 原生 iOS/Android App。
  - 语音和视频通话。
  - 端到端加密（与内容审核和合规留存冲突，见 how.md ADR-004）。
  - 好友关系或长期联系人（会破坏匿名性，以后单独评估）。
  - 付费和会员。
  - 多语言界面（UI 只做简体中文）。
  - 按性别或地理位置匹配。
  - 自研 AI 审核模型（只对接第三方审核接口）。
- **拆分说明:** 按可交付闭环分为 V1 和 V2 两个切片。V1 单实例即可公开上线；V2 依赖 V1 的接口抽象做增量扩展。两个切片放在同一个方案包里，按任务分组，V1 全部完成并验收之后再开始 V2。

## 影响范围
- **模块:** `backend`（identity、verify、realtime、conversation、match、room、bottle、privatechat、moderation、admin、jobs；V2 增加 media、captcha、redisx、push、metrics）、`frontend`（应用壳、WebSocket 客户端、四种聊天形态页面、管理后台）、`deploy`（Compose、Dockerfile、Caddy、备份）。
- **文件:** 全部为新建，目录结构见 how.md。
- **API:** 新建 REST `/api/*`、`/api/admin/*`，WebSocket `/ws`。
- **数据:** 新建 PostgreSQL schema（见 how.md 数据模型）；V2 增加 Redis 和对象存储。

## 核心场景

### 需求: 匿名身份
**模块:** identity / verify

#### 场景: 首次访问自动获得匿名身份
用户第一次打开网站，没有身份 Cookie。
- 服务端签发不透明令牌，写入 HttpOnly Cookie，数据库只存令牌的哈希。
- 页面显示随机昵称（形如"迷路的水獭#3721"）和程序生成的头像。

#### 场景: 一键换身份
用户点击"换个身份"。
- 签发新令牌和新昵称，旧令牌立即失效；旧身份的数据仍按保留期保存，用于审计。
- 用户被封禁期间，IP 和实名账号的封禁对新身份同样生效。

#### 场景: 实名开关开启时需要验证手机号
配置 `VERIFICATION_MODE=required`。
- 未验证的身份发起任何聊天动作都会返回 `verification_required`。
- 手机号用验证码验证通过后绑定到身份；其他用户看不到手机号，管理员也只能看到脱敏后的号码。

### 需求: 随机匹配（A）
**模块:** match / realtime / conversation

#### 场景: 两人匹配成功并聊天
两个在线用户先后点击"开始匹配"。
- 双方都收到 `match.found`，其中只有对方的昵称和头像。
- 双方可以互发消息，看到对方正在输入；消息落库。

#### 场景: 跳过或对方离开
一方点击"下一个"或关闭页面。
- 另一方收到 `match.ended`，原因是 `peer_left`；会话结束，不能再发消息。
- 断线 30 秒内重连可以恢复会话；超过 30 秒视为离开。

#### 场景: 不会匹配到屏蔽过或刚聊过的人
- 匹配器排除双方之间存在屏蔽关系的组合。
- 匹配器排除最近 3 个聊过的对象（队列里人数不足时放宽这一限制）。

### 需求: 聊天室（B）
**模块:** room / realtime / conversation

#### 场景: 进入房间看到历史消息和在线人数
用户从房间列表进入"深夜树洞"。
- 加载最近 50 条消息，可以继续上翻，最多到 7 天前。
- 显示实时在线人数；有人进出时更新。

#### 场景: 房间满员
房间在线人数达到上限（默认 500）。
- 新加入请求返回 `room_full`。

### 需求: 漂流瓶（C）
**模块:** bottle / conversation

#### 场景: 投放和捞取
- 用户投放一段 ≤500 字的瓶子，每日投放次数有上限。
- 捞瓶子时随机拿到一个不是自己投的、未过期、自己没捞过、且双方无屏蔽关系的瓶子；没有可捞的瓶子时返回 `empty_sea`。

#### 场景: 回复瓶子形成异步私聊
捞到的人选择回复。
- 创建一个漂流瓶会话，投放者在"我的瓶子"里看到未读回复；投放者在线时实时推送 `bottle.reply`。
- 捞到的人也可以选择"扔回海里"，瓶子回到池中。

### 需求: 私密链接聊天（D）
**模块:** privatechat / conversation

#### 场景: 创建并分享私密链接
- 用户创建链接，可以设置访问密码、有效期（默认 24 小时，最长 7 天）、是否开启阅后即焚。
- 链接里包含 128 位随机令牌，数据库只存令牌的哈希。

#### 场景: 只允许两人加入
- 第一个打开链接的其他用户成为对方成员；第三个人打开时返回 `link_full`。
- 密码错误时返回 `bad_password`；同一身份或 IP 连续错误会被限流。

#### 场景: 阅后即焚
开启阅后即焚后，接收方阅读了一条消息。
- 接收方阅读后 10 秒，这条消息在双方界面上消失，历史接口也不再返回。
- 服务端仍保留到 7 天期满（用于合规和举报），界面上明确提示"对方仍可截屏"。

#### 场景: 销毁会话
任一方点击"销毁"。
- 会话结束，链接失效，双方都看不到历史；服务端数据按 7 天保留期清除。

### 需求: 消息保留
**模块:** conversation / jobs

#### 场景: 7 天自动清除
- 定时任务分批物理删除创建时间超过 7 天的消息；已结束且消息清空的会话一并清理。
- 举报证据快照和访问审计日志另按 180 天保留（可配置），不受 7 天限制。

### 需求: 内容安全与治理
**模块:** moderation / admin

#### 场景: 敏感词与频率限制
- 命中拦截级敏感词的消息被拒绝，返回 `content_blocked`；命中替换级敏感词的内容会被打码后发送。
- 超过频率限制时返回 `rate_limited`，消息不落库。

#### 场景: 屏蔽与举报
- 用户可以屏蔽当前会话的对方，之后双方互相不可见，也不会再被匹配到一起。
- 举报时服务端生成证据快照（被举报消息及前后上下文），快照独立保存 180 天。

#### 场景: 管理员处理举报并封禁
- 管理员在后台查看举报和证据，可以按身份、IP 或实名账号封禁（临时或永久）。
- 被封禁的在线连接立即断开（`kicked`），之后的握手和请求都返回 `banned`；所有管理操作写入审计日志。

### 需求: 部署
**模块:** deploy

#### 场景: 一条命令启动生产环境
- `docker compose up -d` 启动 postgres、backend、web（Caddy）、backup；Caddy 自动申请 HTTPS 证书。
- 后端启动时自动执行数据库迁移；`/healthz` 返回 200。

### 需求: V2 扩展
**模块:** redisx / match / media / room / captcha / admin / push / metrics

#### 场景: 多实例部署
- 两个后端实例在负载均衡后运行时，连接在不同实例上的用户可以正常匹配、聊天、看到一致的房间在线人数，限流也是全局生效。

#### 场景: 按兴趣匹配
- 选择了相同标签的用户优先匹配；等待超过 10 秒自动回退为随机匹配。

#### 场景: 发送图片
- 支持 jpg/png/webp/gif 格式，大小 ≤5MB；服务端校验文件头、去除 EXIF 并重新编码，然后送审；通过前接收方只看到"图片审核中"；7 天后随消息一起删除。

#### 场景: 自建私密房间
- 房主创建带密码的房间，通过邀请链接加入；房主可以踢人和禁言；7 天没有消息的房间自动归档。

#### 场景: 风控触发人机验证
- 创建身份、发送短信验证码、短时间内多次触发限流时，要求先通过人机验证。

## 风险评估
- **风险: 国内公开上线的合规要求（EHRB：对外发布 + PII）。** 具有"舆论属性或社会动员能力"的即时通讯和聊天室服务，通常需要完成 ICP 备案、公安联网备案、安全评估，提供"后台实名、前台自愿"的身份认证，具备内容审核能力，并留存网络日志不少于 6 个月。
  - **缓解:** 采用"前台匿名、后台可追溯"的设计；实名验证由开关控制（`VERIFICATION_MODE=off|optional|required`）；访问审计日志保留 180 天；敏感词过滤、举报和封禁在 V1 落地。备案、评估和法律文本属于人工事项（HITL 任务 12.3），上线前必须由你和法务确认。本方案不构成法律意见。
- **风险: 匿名平台的骚扰、广告和刷量。**
  - **缓解:** V1 的多维频率限制、敏感词、屏蔽、举报和封禁；V2 的人机验证与风控。换身份无法绕过 IP 和实名账号封禁。
- **风险: 阅后即焚的预期不一致**（用户以为服务端也删除了）。
  - **缓解:** 界面和隐私政策明确说明"对方界面消失，服务端最多保留 7 天用于安全审计，对方仍可截屏"。
- **风险: 手机号属于 PII。**
  - **缓解:** 手机号用 AES-256-GCM 加密存储，用 HMAC-SHA256 做唯一索引；密钥只来自环境变量；后台只显示脱敏号码；日志中禁止出现明文。
- **风险: 单实例故障（V1）。**
  - **缓解:** 客户端自动重连并补拉消息，数据库每日备份；V2 支持多实例。
- **风险: 本机未安装 Docker**，集成测试和部署验证依赖它。
  - **缓解:** 任务 0.2 作为前置 HITL 任务，安装 OrbStack 或 Docker Desktop。
